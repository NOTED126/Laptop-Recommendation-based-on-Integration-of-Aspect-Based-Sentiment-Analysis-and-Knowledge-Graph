# Python and frontend environment setup (Stage 3)

This project has **three distinct execution contexts**:

1. The offline Python research scripts: SemEval preprocessing, DistilBERT ATE/ABSA training and inference, ontology, scoring, scraping, and graph generation.
2. The FastAPI backend: Neo4j-backed API, deployed separately on Render.
3. The React/Vite frontend: built with npm and deployed separately on Render.

**Target local Python**: 3.11 (author's installed version: **3.11.0**). Run Python commands from the **project root** unless explicitly stated otherwise.

## 1. Local Windows PowerShell setup

In a **new copy** of this source repository (not the author's existing `Program/` folder):

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python --version
```

### Install PyTorch first (platform-dependent)

Go to the [official PyTorch installation selector](https://pytorch.org/get-started/locally/) and choose the appropriate Windows, Python, and CPU or NVIDIA GPU build. Execute the selector's **current** installation command. **Do not assume** that the author's Windows CUDA 13.0 build applies to another computer.

The author's original `pip freeze` lists `torch==2.11.0+cu130`, `torchvision==0.26.0+cu130`, and `torchaudio==2.11.0+cu130`. This project directly imports **`torch`**; it does not directly import `torchvision` or `torchaudio`. The latter two are not mandated in `requirements-ml.txt`. If reproducing the author's exact historical environment is important, use a compatible CUDA device and separately preserve the original environment manifest.

Then install the **remaining, directly imported ML/research dependencies**:

```powershell
python -m pip install -r requirements-ml.txt
python -m pip check
```

These versions are transcribed from the installed package list. They are **not** verified as a clean, fully compatible installation on all platforms. In particular, Hugging Face `Trainer` can request additional integration dependencies (such as `accelerate`), which did **not** appear in the provided environment export. If training reports a missing optional integration, install the version it requests and document the change. The author’s historical training metrics should not be presumed reproducible from dependency versions alone.

### Install the API dependencies (same environment or a separate backend venv)

```powershell
python -m pip install -r backend/requirements.txt
Copy-Item backend/.env.example backend/.env
```

Edit the new `backend/.env` with **your own** Neo4j URI and credentials. Never commit it. Run the API from the project root:

```powershell
uvicorn backend.app.main:app --reload
```

**Important:** a fresh GitHub clone has no populated graph or imported review evidence; the API needs access to a compatible, pre-populated Neo4j instance for real recommendations. Neither the SemEval dataset alone nor downloaded model weights populate that graph.

### Install the frontend dependencies

From a separate PowerShell terminal:

```powershell
cd frontend
npm ci
npm run build
npm run dev
```

See `frontend/.env.example` to point the Vite frontend to your backend. The frontend's `VITE_` variables are compiled into client code and must never contain passwords or private tokens.

## 2. Place the downloaded SemEval-2014 data

Download the author's [Kaggle source archive](https://www.kaggle.com/datasets/charitarth/semeval-2014-task-4-aspectbasedsentimentanalysis). The verified `archive.zip` contains two **root-level** files needed by the current preprocessing script:

```text
SemEval_2014_dataset/
├── Laptop_Train_v2.csv
├── Restaurants_Train_v2.csv
└── Final_SemEval.csv       # generated by the next command
```

Only the first two are downloaded; run from the root to generate the third:

```powershell
python Data_preprocessing.py
```

`Data_preprocessing.py` displays Matplotlib plots with `plt.show()`. For unattended execution, those windows may require closing manually or a suitable plotting backend. The training scripts read the generated `Final_SemEval.csv`.

## 4. Offline data-processing directories

`ATE_ABSA_Pipeline.py` outputs predictions into `pipeline_output/` by default **when invoked with `--reviews-dir`**. Omitting `--reviews-dir` runs its sample demo rather than processing files. The raw output can then be explicitly passed to the v3 reaggregation script:

```powershell
python ATE_ABSA_Pipeline.py --reviews-dir reviews --output-dir pipeline_output
python reaggregate_ontology_v3.py --raw pipeline_output/raw_aspect_predictions.csv --output-dir pipeline_output_v3
python recommendation_scoring.py
```

These commands require the complete original laptop review CSVs and the two saved models. The source-only release **does not** include that full corpus. Review CSVs must have the expected `Review` column (the inference script supports `--review-column` if different).

Reaggregation does **not** discover inputs automatically: `--raw` is a required command-line argument, and `--output-dir` defaults to `pipeline_output_v3`. Keep `pipeline_output/` for raw model predictions and `pipeline_output_v3/` for v3 canonical aggregation.
